# Импорт публичных партий Chess.com в ChessMentor

**Вывод на 19.11.2026:** для загрузки завершённых партий достаточно официального Published-Data API и публичного ника. Рекомендуемый первый шаг — ручное обновление из Android-приложения с выбором партий до сохранения. Это источник данных, а не вход в аккаунт и не подтверждение, что ник принадлежит пользователю. Ниже — исследование по документации и коду проекта, а не реализованная функция или отчёт о сетевом тесте.

## Что можно сделать уже сейчас

В браузере открыть `https://api.chess.com/pub/player/{ник}/games/{год}/{месяц}/pgn` (месяц двумя цифрами), скачать PGN, затем в ChessMentor выбрать **«Загрузить» → «Файл .pgn»** и проверить предпросмотр. [Официальный пример для февраля 2025](https://api.chess.com/pub/player/hikaru/games/2025/02/pgn) приведён в [инструкции Chess.com](https://support.chess.com/en/articles/8705305-how-do-i-get-a-pgn-of-my-game). В большом месяце это не импорт без ограничений: действующий пакетный импорт рассматривает первые 50 партий и ограничивает размер текста.

## Как должна работать кнопка «С Chess.com»

| Шаг | Действие игрока | Что делает приложение |
|---|---|---|
| 1. Источник | На экране импорта нажать «С Chess.com», ввести публичный ник | Пояснить: «Загрузим завершённые публичные партии. Пароль не нужен». Сохранять подтверждённый выбор ника только для текущего локального профиля. Дать сменить или забыть его без удаления партий. |
| 2. Период | По умолчанию открыть последний доступный месяц | `GET https://api.chess.com/pub/player/{ник}/games/archives` — получить доступные месяцы. Если список пуст, сообщить «В публичном архиве пока нет партий», а не предлагать повторный вход. |
| 3. Выбор | Увидеть последние 10 партий, выбрать одну или несколько | `GET https://api.chess.com/pub/player/{ник}/games/{YYYY}/{MM}`. В JSON есть `games[].pgn`, `end_time`, `rules`, `white`, `black`, `url`. Взять стандартные шахматы, упорядочить по `end_time` от новых к старым **до** ограничения выборки. Показывать дату, соперника, сторону, результат и пометку «Уже в библиотеке». Выбирать из других месяцев по запросу. |
| 4. Сохранение | Нажать «Импортировать выбранные (N)» | Передать PGN в существующую проверку дубликатов и импорт. До подтверждения не писать в Room и не запускать Stockfish. Цвет определять по нику источника, не по имени локального профиля. При обновлении не менять подсказку ника для ручного импорта Lichess. |

Для такого экрана месячный **JSON** удобнее цельного файла PGN: можно показать конкретные партии до разбора архива. Это разные представления одного источника, не два обязательных скачивания. Форматы и поля: [официальный справочник endpoint’ов](https://www.chess.com/news/view/published-data-api).

## Что переиспользовать и что добавить

- В `AndroidManifest.xml` уже есть `INTERNET`. Форма `UploadGameScreen`, `GameViewModel.onPgnInputChanged`, `PgnParser` и `UploadGameUseCase` уже разбирают PGN и проверяют совпадения по отпечатку в библиотеке данного пользователя. Не заводить второй путь записи партий в Room. Передавать в него только выбранное, не весь месяц с надеждой на автоматическую обрезку.
- Добавить изолированный источник публичного архива: кодировать ник как сегмент пути, обращаться по HTTPS к `api.chess.com`, валидировать год и месяц, ограничить объём читаемого ответа и время ожидания. Если месячный ответ слишком велик — явная ошибка, а не пустой список. При смене ника/месяца отменять старую загрузку. На первый этап не нужны сервер, фоновый опрос или секреты GitHub.
- Официальная справка указывает кеширование вплоть до 12 часов: не обещать появление партии сразу после финиша. Учитывать `Cache-Control`, `ETag`/`Last-Modified` и `304`. Запрашивать месяцы последовательно; на `429` — пауза, без цикла повторов. Для `404`/`410`, отсутствия сети и пустого месяца — разные сообщения. Указать идентифицируемый User-Agent с публичным контактом проекта. [Правила и коды ответов](https://support.chess.com/en/articles/9650547-published-data-api).
- Приложение независимо от Chess.com: явно сказать это на экране источника, не копировать логотип или оформление. PubAPI — только чтение публичных данных; не запрашивать пароль, cookies, доступ к приватным данным и текущим ходам. Если позже понадобится именно авторизация пользователя, это отдельный проект: в справке Chess.com есть форма обращения для разработчиков, а не гарантия выдачи доступа. [Условия PubAPI](https://support.chess.com/en/articles/9650547-published-data-api).

## Проверка перед выпуском

На тестовых JSON-ответах: отсутствующий ник; пустой архив; месяц с 60 партиями (выбираются свежие, не первые 10 старых); другой ник локального профиля; партия за чёрных; повтор из PGN-файла; неподдерживаемый вариант; смена месяца во время загрузки; `304`, `429`, обрыв соединения. Повторный импорт не создаёт копии, а отмена и сетевые ошибки не меняют библиотеку. На устройстве отдельно проверить реальный ответ для публичного ника и доступность сервиса из сети пользователя. Живой сервис не должен быть обязательным условием прохождения CI.
